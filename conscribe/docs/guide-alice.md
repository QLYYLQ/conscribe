# Guide: Framework Developer (Alice)

You're building a config-driven framework with pluggable layers. This guide walks through setting up conscribe from scratch.

## Step 1: Define a Layer

Each pluggable layer needs a registrar. A registrar binds together a Protocol, a registry, and a metaclass.

```python
# my_app/llm/_registrar.py
from typing import Protocol, runtime_checkable
from conscribe import create_registrar

@runtime_checkable
class ChatModelProtocol(Protocol):
    def chat(self, messages: list[dict]) -> str: ...

LLMRegistrar = create_registrar(
    "llm",                              # layer name
    ChatModelProtocol,                  # protocol for compliance checking
    discriminator_field="provider",     # field name in config union
    strip_prefixes=["Chat"],            # ChatOpenAI -> "open_ai"
)
```

Key parameters for `create_registrar()`:

| Parameter | Purpose | Default |
|-----------|---------|---------|
| `discriminator_field` | Config union discriminator name | `""` (required for config) |
| `discriminator_fields` | Discriminator names for nested mode (one per key segment) | `None` |
| `key_separator` | Separator for hierarchical keys, e.g. `"."` | `""` (flat keys) |
| `strip_prefixes` | Prefixes to strip from class names for key inference | `None` |
| `strip_suffixes` | Suffixes to strip from class names for key inference | `None` |
| `key_transform` | Fully custom key inference function | `None` (uses CamelCase->snake_case) |
| `mro_scope` | Scope for MRO `**kwargs` chain resolution | `"local"` |
| `mro_depth` | Max MRO levels to traverse | `None` (unlimited) |
| `skip_pydantic_generic` | Filter Pydantic Generic intermediates | `True` |
| `skip_filter` | Custom class filter callable | `None` |
| `inline_only` | The layer's instances live only inside other layers' receptors (no top-level section in a composed config) | `False` |

## Step 2: Create a Base Class

The base class uses the registrar's metaclass. Mark it `__abstract__ = True` so it's not registered itself.

```python
# my_app/llm/base.py
from my_app.llm._registrar import LLMRegistrar

class ChatBaseModel(metaclass=LLMRegistrar.Meta):
    __abstract__ = True   # not registered
```

## Step 3: Write Implementations

Each subclass is automatically registered. The registry key is inferred from the class name.

```python
# my_app/llm/providers/openai.py
from my_app.llm.base import ChatBaseModel


class ChatOpenAI(ChatBaseModel):
    """OpenAI LLM provider.

    Args:
        model_id: Model identifier, e.g. gpt-4o
        temperature: Sampling temperature, 0-2
    """

    def __init__(self, *, model_id: str, temperature: float = 0.0):
        self.model_id = model_id
        self.temperature = temperature

    def chat(self, messages):
        ...
# Registered as "open_ai" (strip_prefixes=["Chat"] + CamelCase->snake_case)
```

A registry key must be a non-empty string; `__registry_key__ = "custom"` overrides the inferred one, and a list registers the class under several keys. Anything else (an Enum member, a tuple) raises `InvalidRegistryKeyError` when the class is created.

## Step 4: Discover and Use

Import all modules to trigger metaclass registration, then query the registry:

```python
# my_app/main.py
from conscribe import discover
from my_app.llm._registrar import LLMRegistrar

discover("my_app.llm.providers")

llm_cls = LLMRegistrar.get("open_ai")   # -> ChatOpenAI
llm = llm_cls(model_id="gpt-4o")

print(LLMRegistrar.keys())  # ['anthropic', 'open_ai']
```

`discover()` is strict: a module that raises while it is imported stops the call, and the error names the module. Tell it which failures are expected:

```python
discover(
    "my_app.llm.providers",
    allow_missing=["vllm"],               # skip providers whose optional dependency is missing
    exclude=["my_app.llm.providers.dev"], # never import this module or package
)
```

`allow_missing` names the missing dependencies (`vllm`), not your modules; only a `ModuleNotFoundError` for one of them is skipped, including one wrapped in an `ImportError` chain. Registrations made by a module that failed to import are rolled back. Read the failure record with `from conscribe.discover import import_failures`, then `import_failures()`. Wiring and empty-layer errors include that record as a hint about missing imports.

## Step 5: Generate Config Files

Build a discriminated union and write it out as a Python source file and a JSON Schema:

```python
import json
from conscribe import build_layer_config, generate_layer_config_source, generate_layer_json_schema

result = build_layer_config(LLMRegistrar)

with open("generated/llm_config.py", "w") as f:
    f.write(generate_layer_config_source(result))

with open("generated/llm_config.schema.json", "w") as f:
    json.dump(generate_layer_json_schema(result), f, indent=2)
```

The generated file contains per-key Pydantic models and a union type:

```python
# Generated by conscribe 2.1.0
# Auto-generated by conscribe. DO NOT EDIT.
# Layer: llm
# Discriminator: provider
# Entries (2): anthropic, open_ai

from __future__ import annotations

from typing import Annotated, Literal, Union

from pydantic import BaseModel, ConfigDict, Field


class AnthropicLLMConfig(BaseModel):
    model_config = ConfigDict(extra="forbid")

    model_id: str = Field(description='Model identifier')
    max_tokens: int = Field(default=1024, description='Upper bound on generated tokens')
    provider: Literal['anthropic'] = 'anthropic'


class OpenAiLLMConfig(BaseModel):
    model_config = ConfigDict(extra="forbid")

    model_id: str = Field(description='Model identifier, e.g. gpt-4o')
    temperature: float = Field(default=0.0, description='Sampling temperature, 0-2')
    provider: Literal['open_ai'] = 'open_ai'


# Rebuild models for deferred annotation resolution
AnthropicLLMConfig.model_rebuild()
OpenAiLLMConfig.model_rebuild()


LLMConfig = Annotated[
    Union[AnthropicLLMConfig, OpenAiLLMConfig],
    Field(discriminator="provider"),
]
```

The file preserves the in-process `result.union_type` declarations, and the JSON Schema describes their fields, defaults and constraints. Python validators have no JSON Schema form; a validator that cannot be reproduced in source produces an `ExtractionWarning` and a header note. Types from your own modules are imported. A default that cannot be written faithfully (an inline lambda factory that reads a global, an object without a readable form) raises `ConfigRenderError`; the message says what to change.

`build_layer_config()` checks the whole layer before it builds anything: every `__wiring__` problem of every registered class is reported in one `WiringResolutionError`, a typo in an annotation raises `ConfigAnnotationError`, a contradictory declaration raises `ConfigDeclarationError`, and a layer with no classes raises `EmptyLayerError`.

## Step 6: Runtime Validation

Validate user config at startup, before any business logic. This example uses PyYAML (`pip install pyyaml`) to read YAML; JSON configs can use the standard-library `json` module:

```python
from pydantic import TypeAdapter
import yaml

raw = yaml.safe_load(open("experiment.yaml"))
union_type = LLMRegistrar.config_union_type()
config = TypeAdapter(union_type).validate_python(raw["llm"])
# ValidationError here, at startup, if the config is invalid

llm = LLMRegistrar.get(config.provider)(**config.model_dump(exclude={"provider"}))
```

## Step 7: Check Your Declarations in Tests

Run conscribe's checks in your test suite, so a broken declaration fails in CI before it reaches a user:

```ini
# pytest.ini
[pytest]
filterwarnings =
    error::conscribe.ConscribeWarning
```

```python
# conftest.py
pytest_plugins = ["conscribe.testing.pytest_plugin"]
```

```python
# tests/test_layers.py
from conscribe import build_composed_config, discover, validate_wiring
from my_app.agents import AgentRegistrar
from my_app.llm import LLMRegistrar

LAYERS = {"llm": LLMRegistrar, "agent": AgentRegistrar}

def test_layers_build():
    discover("my_app.llm.providers", "my_app.agents")
    validate_wiring(LAYERS)          # every wiring problem, in one error
    build_composed_config(LAYERS)    # the other build-time declaration problems
```

The warning filter turns conscribe's warnings (a field type degraded to `Any`, a signature conscribe cannot read) into failures. The plugin provides the `conscribe_isolated` fixture: classes a test defines are unregistered when it ends. See [Testing](testing.md). Problems that only show when a file is written (`ConfigRenderError`) need the generation step itself; the freshness test in [Keeping Generated Files Fresh](#keeping-generated-files-fresh) covers them.

## Integrating External Classes

### Path A: Already Inherits Base

If an external class already extends your base, its subclasses auto-register:

```python
from cool_agent import CoolAgent  # extends BaseAgent

class MyCool(CoolAgent):           # auto-registered as "my_cool"
    ...
```

### Path B: Bridge (recommended)

For classes that don't use your metaclass:

```python
from ext_framework import ExtAgent

ExtBridge = AgentRegistrar.bridge(ExtAgent)

class MyExtV1(ExtBridge):   # auto-registered as "my_ext_v1"
    ...
class MyExtV2(ExtBridge):   # auto-registered as "my_ext_v2"
    ...
```

`bridge()` automatically resolves metaclass conflicts using four strategies:
1. External is plain `type` -> use our Meta
2. Our Meta subclasses external's -> use ours
3. External is more specific -> use theirs
4. Incompatible -> dynamically create combined metaclass

### Path C: Decorator (one-off)

```python
@AgentRegistrar.register("custom_agent")
class CustomAgent:
    def step(self): ...
```

Use `propagate=True` to also auto-register future subclasses:

```python
@AgentRegistrar.register("base_ext", propagate=True)
class ExtBase:
    def step(self): ...

class SubExt(ExtBase):  # auto-registered as "sub_ext"
    def step(self): ...
```

Put `@register(...)` above `@dataclass(slots=True)` or `attrs.define` when you stack them: those decorators replace the class with a new one.

## Advanced: Hierarchical Keys

For layers with natural hierarchies (e.g., model_type → provider), use `key_separator` and `discriminator_fields`:

```python
LLM = create_registrar(
    "llm", ChatModelProtocol,
    discriminator_fields=["model_type", "provider"],
    key_separator=".",
)

# Abstract parent defines level 0 params
class OpenAIBase(metaclass=LLM.Meta):
    __registry_key__ = "openai"
    __abstract__ = True
    def __init__(self, *, temperature: float = 0.7, max_tokens: int = 1000):
        ...

# Leaf children define level 1 params
class AzureOpenAI(OpenAIBase):
    __registry_key__ = "openai.azure"
    def __init__(self, *, deployment: str, api_version: str = "2024-02", **kwargs):
        super().__init__(**kwargs)

class OfficialOpenAI(OpenAIBase):
    __registry_key__ = "openai.official"
    def __init__(self, *, endpoint: str, **kwargs):
        super().__init__(**kwargs)
```

A parameter belongs to the level of the root-most class whose own constructor accepts it: `temperature` and `max_tokens` are level 0, `deployment` and `api_version` level 1. Every registered key must have exactly one segment per discriminator field; a key with the wrong number of segments raises `ConfigDeclarationError`.

### Tree Queries

```python
LLM.children("openai")
# → {"openai.azure": AzureOpenAI, "openai.official": OfficialOpenAI}

LLM.tree()
# → {"openai": {"azure": AzureOpenAI, "official": OfficialOpenAI}}
```

### Generated Nested Config

Config files use compound discrimination with nested sub-models:

```yaml
# experiment.yaml (hybrid format)
llm:
  model_type: openai           # flat (level 0 discriminator)
  temperature: 0.7             # flat (level 0 param)
  max_tokens: 1000
  provider:                    # nested (level 1)
    name: azure
    deployment: my-deployment
    api_version: 2024-02
```

Nested-mode layers do not support `__wiring__`, `__config_schema__`, `__config_from_param__`, `__config_mro_scope__` or `__config_mro_depth__` on their classes yet; each raises `ConfigDeclarationError`.

## Advanced: Wiring Layers Together

A class declares which implementations of another layer it works with in `__wiring__`. The config field then only accepts those keys:

```python
class BaseAgent(metaclass=AgentRegistrar.Meta):
    __abstract__ = True
    __wiring__ = {"llm": "llm"}              # every key of the "llm" layer

    def step(self) -> None: ...


class Planner(BaseAgent):
    __wiring__ = {"memory": "memory"}        # no parameter: the framework sets it

    def __init__(self, *, llm: object, max_steps: int = 20):
        self.llm = llm
        self.max_steps = max_steps
```

```python
class PlannerAgentConfig(BaseModel):
    model_config = ConfigDict(extra="forbid")

    llm: Literal['anthropic', 'open_ai']  # wired from: llm
    max_steps: int = 20
    memory: Optional[Literal['local']] = None  # wired from: memory
    name: Literal['planner'] = 'planner'
```

`llm` is a constructor parameter, so your framework passes the built LLM to `Planner(...)`. `memory` has no parameter or annotation: it is an attribute your framework sets after construction. Until it does, reading it raises a clear error, because conscribe installed a `WiredField` placeholder:

```python
planner = Planner(llm=LLMRegistrar.get("open_ai")(model_id="gpt-4o"))
try:
    planner.memory
except AttributeError as exc:
    print(exc)

planner.memory = LocalMemory()   # the framework injects
```

```
Wired attribute 'memory' on Planner has not been injected yet. Expected injection from registry 'memory'.
```

`conscribe.introspect` tells your framework where each wired value goes, by the same rules conscribe uses to build the config:

```python
from conscribe.introspect import wiring_slots

for name, entry in wiring_slots(Planner).items():
    where = entry.slot.via if entry.slot else "setattr after construction"
    print(name, entry.spec.registry_name, where)
```

```
llm llm init
memory memory setattr after construction
```

More wiring options are in the [Recipes](recipes.md): explicit key subsets, a `default` key, `declare_only` entries for constraints your framework only reads, capability-relative keys, and `.pyi` stubs so type checkers see injected attributes. Every wiring problem is an error, reported for all classes at once.

## Advanced: Composed Config (Multi-Layer Inline Wiring)

When your framework has multiple layers wired together, generate a single composed schema. Wired fields become inline config objects instead of key selectors:

```python
from conscribe import build_composed_config, generate_composed_json_schema
import json

result = build_composed_config(
    {"llm": LLMRegistrar, "agent": AgentRegistrar},
    inline_wiring=True,
)

schema = generate_composed_json_schema(result)
with open("generated/composed.schema.json", "w") as f:
    json.dump(schema, f, indent=2)
```

Users can then write YAML with full IDE autocompletion across layers:

```yaml
agent:
  - name: browser_use
    use_vision: true
    llm:                          # IDE autocompletes all LLM config fields
      provider: open_ai
      model_id: gpt-4o
      temperature: 0.7
```

Layers are topologically sorted by wiring dependencies (leaves first). Circular wiring raises `CircularWiringError`, naming the cycle.

The top-level model only accepts layer names: a misspelled section is a validation error, and the JSON Schema says `additionalProperties: false`. If your config files carry other sections that your application reads itself, relax it:

```python
result = build_composed_config(
    {"llm": LLMRegistrar, "agent": AgentRegistrar},
    top_level_extra="ignore",   # drop unknown top-level sections instead of refusing them
)
```

A layer whose instances only make sense inside another layer (an archiver used by a trace-writing hook, say) can be declared inline-only. It gets no top-level section, and writing it there fails with a message that lists the receptors where its instances go:

```python
Archiver = create_registrar("archiver", ArchiverProtocol, discriminator_field="name", inline_only=True)
```

See the [Recipes](recipes.md) for inline-only layers and default instances.

CLI equivalent:

```bash
conscribe generate-composed-config \
  --registrar my_app.llm:LLMRegistrar \
  --registrar my_app.agents:AgentRegistrar \
  --discover my_app.llm.providers \
  --format json-schema \
  --output generated/composed.schema.json
```

## Advanced: Cross-Registry Diamond Inheritance

Register a class in multiple registries using the `|` operator:

```python
LLM = create_registrar("llm", LLMProtocol, discriminator_field="provider")
Agent = create_registrar("agent", AgentProtocol, discriminator_field="name")

CombinedMeta = LLM.Meta | Agent.Meta

class LLMAgentBase(metaclass=CombinedMeta):
    __abstract__ = True
    def chat(self, messages: list) -> str: ...
    def step(self) -> None: ...

class MyLLMAgent(LLMAgentBase):
    ...
# MyLLMAgent is in BOTH LLM and Agent registries
```

Registration is atomic: if the class cannot be registered in the second registry (a duplicate key, say), it is removed from the first one too before the error propagates.

### Selective Opt-Out

```python
class LLMOnly(LLMAgentBase):
    __skip_registries__ = ["agent"]
# Only in LLM registry
```

### Parent Registration Control

```python
class StrictBase(metaclass=LLM.Meta):
    __abstract__ = True
    __propagate_depth__ = 1  # only direct children register

    @staticmethod
    def __registration_filter__(child_cls):
        return "Test" not in child_cls.__name__  # block test classes
```

## Pydantic BaseModel + Generic[T]

When Pydantic specializes `BaseModel[T]`, it creates real class objects that would pollute the registry. Conscribe filters these automatically (`skip_pydantic_generic=True` by default).

```python
from pydantic import BaseModel
from typing import Generic, TypeVar

T = TypeVar("T")
class BaseEvent(BaseModel, Generic[T]):
    payload: T

EventBridge = EventRegistrar.bridge(BaseEvent)

class StringEvent(EventBridge):
    payload: str = "hello"
# BaseEvent[str] intermediates are filtered out automatically
```

Config extraction also works -- fields are read from `model_fields` instead of `__init__`. Validators defined on such a registered model are not part of its config model; they run when your framework instantiates the class. If configs must pass them at load time, give the class a `__config_schema__`.

## Keeping Generated Files Fresh

Generated files go stale when someone adds a provider or changes a parameter. A test catches that:

```python
from pathlib import Path
from conscribe import build_layer_config, discover, generate_layer_config_source
from my_app.llm import LLMRegistrar

def test_generated_llm_config_is_current():
    discover("my_app.llm.providers")
    expected = generate_layer_config_source(build_layer_config(LLMRegistrar))
    assert Path("generated/llm_config.py").read_text() == expected, (
        "generated/llm_config.py is stale: run conscribe generate-config"
    )
```

To detect config changes, store a fingerprint next to the files. `compute_registry_fingerprint()` hashes the layer's config source, JSON Schema, conscribe version and layer settings:

```python
from conscribe import compute_registry_fingerprint, load_cached_fingerprint, save_fingerprint

cache = Path("generated/.fingerprints.json")
current = compute_registry_fingerprint(LLMRegistrar)
if load_cached_fingerprint(cache, "llm") != current:
    ...  # regenerate the llm files, then:
    save_fingerprint(cache, "llm", current)
```

Stubs are not hashed; regenerate `.pyi` files separately. For composed configs, track every participating layer and the composition options (`inline_wiring` and `top_level_extra`).

## Design Principles

- **Zero registration burden** -- Inherit a base class = registered
- **`__init__` is the single source of truth** -- No duplicate config definitions
- **Fail-fast** -- A declaration conscribe cannot honour raises at class creation or build time, and the message says how to fix it
- **Domain-agnostic** -- Pure infrastructure, knows nothing about agents or LLMs
- **Stubs and runtime are separate** -- Stubs only help type checkers; stale ones are reported
