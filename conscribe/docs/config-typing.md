# Config Typing Deep-Dive

`conscribe/config/` turns registered classes into pydantic config models, generated Python source and JSON Schema. For usage, see [Guide: Framework Developer](guide-alice.md) and [Guide: Framework User](guide-bob.md); for signatures, see the [API Reference](api-reference.md#config-typing).

## Pipeline overview

```
extract_config_schema(cls)              # per class: constructor + __wiring__ -> pydantic model
        |
build_layer_config(registrar)           # per layer: validate_wiring, then a discriminated union
        |                                 (flat mode or nested mode)
build_composed_config(registrars)       # several layers: one top-level model, inline wiring
        |
        +-> generate_layer_config_source / generate_composed_config_source   # Python source
        +-> generate_layer_json_schema   / generate_composed_json_schema     # JSON Schema
        +-> compute_registry_fingerprint                                     # hash of the outputs
```

Three artifacts come out of a build: the in-process models, the generated Python source and the JSON Schema. They share the same field declarations; validation metadata the source cannot carry is reported explicitly (see [Three artifacts, one config](#three-artifacts-one-config)).

## Extraction (`extractor.py`)

`extract_config_schema(cls, mro_scope="local", mro_depth=None)` turns one class into the pydantic model that validates its config block. The builder adds the discriminator afterwards. It tries, in order:

1. Tier 3, `__config_schema__`: the schema, used verbatim after its wiring checks (see [Tier 3](#tier-3-__config_schema__)).
2. `__config_from_param__ = "<param>"`: the flattened model of one `BaseModel` parameter (see [Single-parameter models](#single-parameter-models-__config_from_param__)).
3. Constructor reflection: a model with one field per configurable constructor parameter (a *knob*), plus the wiring receptors. Tier 1 reads types and defaults, Tier 1.5 adds docstring descriptions, and Tier 2 carries `Annotated` / `Field` metadata.
4. `None` when the class has no constructor parameter a config can set, no `__wiring__` entry, and a constructor without `*args` / `**kwargs` (the model would be empty and closed). The builder then uses a discriminator-only model.

Every path, Tier 3 included, resolves the class's wiring.

### Which parameters

conscribe reads the constructor the way Python calls it (`conscribe.config.mro.walk_init_chain`, the same rule `conscribe.introspect` exposes):

- a hand-written `__init__`, following `**kwargs` forwarding up the MRO (see [MRO and Type Degradation](mro-and-degradation.md));
- `__init__` methods generated by `@dataclass` and attrs, with the real defaults and factories of their fields;
- pydantic models whose own `__init__` only forwards `**data`: their `model_fields`;
- pydantic dataclasses: their fields;
- a class with no `__init__` anywhere in its MRO: no constructor fields, `extra="forbid"`.

Some parameters cannot be config fields:

| Parameter | Result |
|-----------|--------|
| Positional-only (`x, /`) | Skipped when it has a default; `ConfigDeclarationError` when the constructor requires it |
| Name starting with `_` | Same (pydantic never makes such a name a field) |
| A `model_*` name that is a `BaseModel` member (`model_config`, `model_dump`, ...) | `ConfigDeclarationError` |
| `*args` / `**kwargs` | Not fields; they decide the extra policy (below) |

A registered `BaseModel` (or pydantic dataclass) gets a config model rebuilt from its fields on a fresh `BaseModel`. It is never derived from the registered class, which would register the config model and run the class's `__init__`. As a result, the class's own validators and `model_config` (apart from `extra`) do not apply to its config: they run when the framework instantiates the class. Use `__config_schema__` for validation at YAML time.

### Annotation resolution

Each annotation is evaluated in the namespace of the class that *declares* it, like `typing.get_type_hints` does:

| Declared in | Resolved in |
|-------------|-------------|
| A hand-written `__init__` | The function's module globals, then builtins (the class namespace only as a last resort) |
| A dataclass or attrs field, also inherited | The module of the class that declares the field |
| A class-level annotation | The class's module, then the class namespace |
| A pydantic model or pydantic dataclass field | The type pydantic resolved |

An inherited field written under `from __future__ import annotations` therefore resolves in its own module, not the subclass's. conscribe never imports anything to resolve a name, and there is no fallback that injects `typing` names: a module must import `Optional`, `Field` and anything else its annotations use.

When an annotation cannot be resolved:

| Situation | Result |
|-----------|--------|
| A name the declaring module only imports under `if TYPE_CHECKING:` | The field's type degrades to `Any` (default, description and constraints kept), with a `DegradationWarning` and a `DegradedField(reason="type_checking_only")` |
| A name local to the function that defines the class | The field's type degrades to `Any`, with an `ExtractionWarning` instead of a `DegradationWarning`, and reason `"function_locals"` |
| A name found nowhere (module globals, class namespace, builtins, `TYPE_CHECKING` imports) | `ConfigAnnotationError`: a typo or a missing import |
| `Annotated` metadata that cannot be evaluated (e.g. `Field` imported only under `TYPE_CHECKING`) | `ConfigAnnotationError` |

Wired receptors never fail on an unresolvable annotation: their config type comes from the wiring keys, and their shape is read from the annotation text. Warnings point at the class statement in your file.

```python
# typed_clients.py
from __future__ import annotations

from typing import TYPE_CHECKING

if TYPE_CHECKING:
    from decimal import Context


class Priced:
    def __init__(self, price: int = 1, ctx: Context | None = None) -> None:
        self.price = price


class Typo:
    def __init__(self, timeout: Flaot = 1.0) -> None:  # noqa: F821
        self.timeout = timeout
```

### Field metadata (Tier 2) and docstrings (Tier 1.5)

Everything written in `Annotated[T, Field(...)]`, or in a `Field(...)` used as the default value (`x: int = Field(1, ge=0)`), is carried into the config field: title, description, examples, `json_schema_extra`, the alias family (`alias`, `validation_alias`, `serialization_alias`), `discriminator`, constraints (`gt`, `pattern`, `max_length`, `strict`, ...), `frozen`, `validate_default`, `repr`. Other `Annotated` metadata (validators, `annotated_types` constraints, markers) stays on the type. Two exceptions:

- `Field(exclude=...)` on a constructor parameter is a `ConfigDeclarationError`: a config carries constructor arguments, and an excluded field would be missing from `model_dump()`. On a field of a registered pydantic model (`api_key: SecretStr = Field(exclude=True)`) it is a serialization choice of the model and is not carried.
- `Field(deprecated=...)` becomes the JSON-schema marker `"deprecated": true` only, never pydantic's runtime `DeprecationWarning`.

Aliases change the keys a config accepts: a parameter declared with `Field(alias="apiKey")` is written `apiKey:` in YAML.

When no `Field` gives a description, the class docstring (or the `__init__` docstring) supplies it: Google, NumPy or reST style, `Args:` or `Attributes:` sections. This needs the optional `docstring-parser` dependency (`pip install conscribe[docstring]`).

```python
from typing import Annotated

from pydantic import AfterValidator, Field

from conscribe import extract_config_schema


def positive(value: int) -> int:
    if value <= 0:
        raise ValueError("must be positive")
    return value


class Client:
    """An HTTP client.

    Args:
        base_url: Where requests go.
        timeout: Seconds per request.
    """

    def __init__(
        self,
        base_url: str,
        timeout: Annotated[float, Field(gt=0, title="Timeout (s)", examples=[5.0])] = 10.0,
        api_key: Annotated[str, Field(alias="apiKey")] = "",
        retries: Annotated[int, AfterValidator(positive)] = None,
        legacy: Annotated[bool, Field(deprecated="use base_url")] = False,
    ) -> None: ...


Config = extract_config_schema(Client)
for name, field in Config.model_fields.items():
    print(f"{name}: {field}")
print(Config(base_url="https://example.com", apiKey="k", retries=None))
print(Config.model_json_schema()["properties"]["legacy"])
```

### The None rule

A `None` default makes the field's type admit `None` (`x: T = None` becomes `Optional[T]`), identically on every Python version. Validators and other schema hooks on `T` move inside the `Optional`, so they never see `None`: in the example above, `retries` accepts `None` without running `positive`. `Optional[Annotated[T, Field(...)]]` keeps its `Field`.

### Defaults and factories

A field's default comes from exactly one source: the signature or a `Field(default=...)` / `Field(default_factory=...)`. When both define one and they differ, conscribe raises `ConfigDeclarationError` naming both; equal defaults are fine.

Factories are read from where they are declared: `dataclasses.field(default_factory=...)`, attrs `Factory`, pydantic `default_factory`. The stand-ins for them (`<factory>`, attrs `NOTHING`, `PydanticUndefined`, `...`) never become a default value in a model, a generated file or a schema. (A field whose default comes from a factory has no plain default, which pydantic reports as `default=PydanticUndefined`; see the example below.)

A factory conscribe can prove *pure* is evaluated twice and, when both results are equal, becomes a plain default in all three artifacts (pydantic copies mutable defaults per instance). When the two results differ, it stays a factory. Pure means:

- a builtin container constructor (`list`, `dict`, `set`, `tuple`, `frozenset`); or
- a plain zero-argument function or lambda with no closure that reads no global name except side-effect-free builtins (`len`, `range`, `sorted`, `str`, ...; not shadowed in its module), and does not import, create classes, write globals or touch dunder attributes.

Any other factory stays a `default_factory`: the in-process model calls it per instance, the generated source imports it by reference, and the JSON Schema shows no default. Only a module-level object can be imported, so an impure lambda or nested function makes `generate_*_source` raise `ConfigRenderError` (the in-process model still works). A pure factory that raises when conscribe evaluates it is a `ConfigDeclarationError`; impure factories are never called at build time. An attrs `Factory(takes_self=True)` cannot be expressed in a config; the field is required and an `ExtractionWarning` says why.

```python
from dataclasses import dataclass, field
from typing import Protocol, runtime_checkable

from conscribe import build_layer_config, create_registrar, generate_layer_config_source
from job_types import default_workdir   # def default_workdir(): return os.environ.get(...)


def default_tags() -> list[str]:
    return ["prod"]

result = build_layer_config(Jobs)
for name, info in result.per_key_models["backup"].model_fields.items():
    factory = getattr(info.default_factory, "__name__", None)
    print(f"{name}: default={info.default!r} default_factory={factory}")
print(generate_layer_config_source(result))
```

### `__config_annotated_only__`

With `__config_annotated_only__ = True`, only parameters declared with a `Field` (in `Annotated` metadata or as the default value) become config fields. Wiring receptors are fields regardless, and so are the fields of pydantic models and pydantic dataclasses.

### Extra policy

The first row that matches applies:

| Constructor | `extra` |
|-------------|---------|
| A pydantic model or pydantic dataclass, also at the end of a `**kwargs` chain | Its own `extra` setting, `"forbid"` when unset |
| A `**kwargs` chain cut by the MRO scope or depth, an unreadable signature or a Protocol placeholder `__init__` that swallows its arguments (`typing_extensions` before Python 3.12; the last two with an `ExtractionWarning`) | `"allow"` |
| `**kwargs` forwarded to parents that contribute parameters, the chain ending naturally (at a parent without `**kwargs`) | `"forbid"` |
| `**kwargs` through which no parent contributes a parameter (the class keeps them, or forwards them to a parent that takes none) | `"allow"` |
| `*args` | `"allow"` |
| No `*args` / `**kwargs` | `"forbid"` |

### Wired fields

During constructor reflection, every merged `__wiring__` entry becomes a field whose value is a registry key (a literal value for a [Mode 3](api-reference.md#__wiring__-entries) list), so its type is built from the wiring keys. A private entry name such as `_client` passes the wiring grammar check but raises `ConfigDeclarationError` here because pydantic cannot expose it as a field. A [Tier-3 schema](#tier-3-__config_schema__) supplies its own fields and may omit entries without runtime slots.

The parameter or attribute named by a wiring entry is its *receptor*. It has a *runtime slot* when the class declares an `__init__` parameter (also one forwarded through `**kwargs`) or a non-`ClassVar` class annotation anywhere in the MRO. Slot-less receptors are attributes the framework can assign after construction; `declare_only` entries are constraints for which it assigns nothing.

- The receptor's annotation decides the shape. Each non-`None`, non-container member of a union maps to `Literal[<keys>]` (deduplicated). Container members (`list`, `tuple`, `set`, `dict` and other mappings, ...) map to `list[Literal[<keys>]]`, one key per wired instance (a mapping receptor too). `None` stays, and `Annotated` metadata is kept. `Protocol | None` therefore becomes `Optional[Literal[...]]`.
- A user-written `Literal[...]` in a wired annotation must list only wiring keys; otherwise `ConfigDeclarationError`.
- On a single-instance receptor, key-string constraints (`pattern`, `min_length`, `max_length`) narrow the allowed keys at build time. Constraints that reject every key are a `ConfigDeclarationError`.
- A receptor with a runtime slot is required unless its default says otherwise; a class-annotation slot without a value is optional (default `None`) only when its annotation admits `None`. A class-body value (`hooks: list[P] = []`) is the default.
- A non-`None` default of the receptor must be a valid value of the field (an allowed key, or a list of them for a container receptor). `None` is always accepted.
- A slot-less entry and a `declare_only` entry are `Optional[Literal[...]] = None`. A config may name a key there, but nothing receives a value at construction time, so the field is never required.
- The dict-form `default` makes the field optional with that key as default. When the receptor's annotation admits `None`, it stays `Optional`: an omitted value means the default key, `null` means `None`. A parameter default naming another key is an error (`bad_default`).

conscribe collects every wiring problem of the class (unknown keys or registries, bad defaults, `declare_only` contradictions) and raises them together in one `WiringResolutionError`. Contradictions in a receptor's own annotation (a `Literal` member that is not a key, key constraints that reject every key) are a `ConfigDeclarationError`.

```python
from typing import Optional, Protocol, runtime_checkable
```

### Tier 3: `__config_schema__`

`__config_schema__` must be a `BaseModel` subclass, or `InvalidConfigSchemaError` is raised (at class creation for classes the metaclass registers, and at extraction). Extraction returns the schema itself. The builder subclasses it to add the discriminator, preserving its fields, validators and `model_config`, except that unset `extra` becomes `"forbid"` on the per-key model. The class's wiring is still resolved:

- every wired entry with a runtime slot must be a field of the schema (`ConfigDeclarationError` otherwise); slot-less and `declare_only` entries need not be;
- an entry's `default` must equal the schema field's default;
- a schema field typed with `Literal[...]` narrows the wired keys, so an inline composed field accepts exactly what the per-layer model accepts;
- in composed builds, Tier-3 owners are inlined like any other.

A schema with a `@computed_field` dumps that field, and an `extra="forbid"` schema then refuses it when the dump is validated again. Leave computed fields out of config schemas.

```python
from typing import Literal, Protocol, runtime_checkable

from pydantic import BaseModel, ValidationError, field_validator

from conscribe import build_layer_config, create_registrar


@runtime_checkable
class Component(Protocol):
    def run(self) -> None: ...


Loop = create_registrar("loop", Component, discriminator_field="name")
Agent = create_registrar("agent", Component, discriminator_field="name")


class LoopBase(metaclass=Loop.Meta):
    def run(self) -> None: ...


class React(LoopBase):
    __registry_key__ = "react"


class Plan(LoopBase):
    __registry_key__ = "plan"


class SweSchema(BaseModel):
    loop: Literal["react"] = "react"
    max_steps: int = 10

    @field_validator("max_steps")
    @classmethod
    def _cap(cls, value: int) -> int:
        if value > 100:
            raise ValueError("max_steps must be <= 100")
        return value


class AgentBase(metaclass=Agent.Meta):
    def run(self) -> None: ...


class Swe(AgentBase):
    __config_schema__ = SweSchema
    __wiring__ = {"loop": "loop"}

    def __init__(self, loop: Component, max_steps: int = 10) -> None: ...


model = build_layer_config(Agent).per_key_models["swe"]
print([cls.__name__ for cls in model.__mro__[:3]], model.__wired_keys__)
try:
    model(max_steps=500)
except ValidationError as exc:
    print(exc.errors()[0]["msg"])
```

```
Value error, max_steps must be <= 100
```

### Single-parameter models: `__config_from_param__`

In 1.x a class whose own `__init__` took exactly one `BaseModel` parameter had its config flattened to that model's fields. In 2.0 that parameter is an ordinary nested block unless the class opts in:

```python
__config_from_param__ = "settings"   # inherited; None opts out
```

The opt-in is validated strictly: it must name a constructor parameter annotated with a plain `BaseModel` subclass (not `Optional`, not a union, not a `RootModel`, not a registered class); the parameter must not be a wiring receptor; every other constructor parameter must be a wiring receptor; its default may be absent or an instance of the model (whose values become the field defaults), never `None`. The flattened model subclasses the parameter's model (its validators apply), keeps the class's wiring receptors and carries `__config_from_param__`. It is not supported in nested-mode layers.

For one major version, the models of classes 1.x would have flattened reject the old flat keys with a pydantic error of type `legacy_flat_config` (`conscribe.config.extractor.LEGACY_FLAT_ERROR`):

```python
from typing import Protocol, runtime_checkable

from pydantic import BaseModel, ValidationError

from conscribe import build_layer_config, create_registrar


@runtime_checkable
class Runnable(Protocol):
    def run(self) -> None: ...


Tool = create_registrar("tool", Runnable, discriminator_field="kind")


class ToolBase(metaclass=Tool.Meta):
    def run(self) -> None: ...


class SearchSettings(BaseModel):
    engine: str = "bing"
    top_k: int = 5


class Search(ToolBase):
    def __init__(self, settings: SearchSettings) -> None: ...


class FlatSearch(ToolBase):
    __config_from_param__ = "settings"

    def __init__(self, settings: SearchSettings = SearchSettings(top_k=3)) -> None: ...


models = build_layer_config(Tool).per_key_models
print(models["search"](settings={"engine": "ddg"}))
try:
    models["search"](engine="ddg")
except ValidationError as exc:
    print(exc.errors()[0]["type"], "|", exc.errors()[0]["msg"])
print(models["flat_search"](engine="ddg"))
```

```
settings=SearchSettings(engine='ddg', top_k=5) kind='search'
legacy_flat_config | 'settings' is a nested block in conscribe 2.0; write {settings: {...}} or set __config_from_param__ = 'settings'
engine='ddg' top_k=3 kind='flat_search'
```

### Model attributes

Every model conscribe builds carries `__conscribe_generated__ = True` in its own `__dict__`, plus, when they apply: `__wired_fields__` (`{field: registry}`), `__wired_keys__` (`{field: allowed keys}`), `__wired_defaults__` (`{field: default key}`), `__degraded_fields__`, `__config_from_param__` and `__legacy_flat_keys__`. Composed builds add `__inline_wired__`. See [Class attributes](api-reference.md#class-attributes).

### `extract_own_init_params(cls)`

`conscribe.config.extractor.extract_own_init_params(cls)` is a compatibility helper kept from 1.x. It returns the named parameters of `cls`'s own `__init__` that the nearest parent constructor does not already take, as `(list[inspect.Parameter], {name: annotation})`, with annotations resolved in the declaring class's namespace (raw when unresolvable); `([], None)` when `cls` defines no constructor. It applies none of the field rules above. The nested-mode builder no longer uses it.

## Building (`builder.py`)

`build_layer_config(registrar)` works in three steps:

1. Check what cannot be built at all: not a registrar (`TypeError`), no discriminator (`ValueError`), an empty layer (`EmptyLayerError`, citing the modules `discover()` failed to import), and in nested mode keys with the wrong number of segments and unsupported declarations (`ConfigDeclarationError`).
2. Validate the wiring of every registered class (`validate_wiring`), so all wiring problems of the layer are reported in one `WiringResolutionError`.
3. Build every per-key model, in flat or nested mode.

### Flat mode (`discriminator_field`)

For each registered key, the extracted model (or a discriminator-only model when extraction returned `None`) gets the discriminator field `Literal[key]` with default `key`.

- The per-key model *subclasses* the model it is built from (the extracted model, a Tier-3 schema), so validators, `model_config` and `FieldInfo` objects survive. conscribe sets the extra policy explicitly: a source that does not set `extra` stays `"forbid"`, where pydantic's default would be `"ignore"`.
- A source model with an `alias_generator` gets the discriminator declared with `alias=<field>`, so the generator cannot rename it.
- The discriminator would overwrite a config field whose name or alias is the discriminator field, so such a field is a `ConfigDeclarationError`.
- A `RootModel` or a registered class as config schema is refused: subclassing a registered class would register the config model as an implementation.
- A source model left incomplete by forward references is rebuilt in its own module first; one that stays incomplete is a `ConfigDeclarationError` naming the missing names.

The union is the model itself for a one-key layer, otherwise `Annotated[Union[...], Field(discriminator=...)]`.

### Model names

Per-key model names are `{KeyPart}{LayerPart}Config`. The key's words are title-cased and joined: `browser_use` gives `BrowserUse`, `openai.azure` gives `OpenaiAzure` and `gpt-4o` gives `Gpt4O`. A layer name of up to three characters is upper-cased (`llm` gives `LLM`, `job` gives `JOB`), a longer one title-cased (`agent` gives `Agent`). Nested-mode segment blocks are named `{Segment}{Field}Config` (`AzureProviderConfig` for segment `azure` of the `provider` level). Names are valid identifiers (a name that would start with a digit starts with `_`) and unique per build: a later model whose name is taken gets the next numeric suffix (`WebSearchToolsConfig2`), in build order, so names are deterministic.

### Nested mode (`discriminator_fields`)

A registrar created with `discriminator_fields=["model_type", "provider"]` and `key_separator="."` builds one nested model per key: level 0's discriminator and parameters sit flat at the top, and each further level is a block holding that segment's `name`, its parameters and the next block. Every registered key must have exactly one segment per discriminator field.

Parameters follow the leaf's real constructor: the fields of a key are what its class's constructor accepts (hand-written `__init__` with `**kwargs` forwarding, dataclass and attrs generated ones, pydantic fields), built with the same rules as flat mode: `Field` carry, factories and the purity gate, the None rule, annotation degradation and errors, `__config_annotated_only__`, docstrings. A parameter's *level* is the level of the root-most class in the MRO whose own constructor accepts it. A class's level is the segment count of its `__registry_key__` (own or inherited) minus one; a class without a key takes the level of the nearest keyed class on the leaf side. When no parameter lands on level 0, the deepest level's parameters move up to level 0 (single-provider families such as `google.default`).

Other rules:

- A segment block is optional when none of its fields is required. Its default is an instance, or `Field(default_factory=<block model>)` when a field uses a factory.
- The compound discriminator joins the level-0 value and each block's `name`; a missing block or `name` reads as `"default"`, so a segment registered as `default` is selected by omitting it. A part that is not a string yields no tag (pydantic reports `union_tag_not_found`).
- A constructor whose signature cannot be read cuts the chain: an `ExtractionWarning`, and the models of that class's level and of every level closer to level 0 accept unknown keys.
- Structurally identical segment models (for example the parameter-less `default` provider of several families) are built once and shared.
- Not supported on nested-mode classes yet, each a `ConfigDeclarationError`: `__wiring__`, `__config_schema__`, `__config_from_param__`, `__config_mro_scope__`, `__config_mro_depth__`, and parameters whose name or alias collides with a discriminator, a segment block or a segment `name`. The registrar's `mro_scope` / `mro_depth` have no effect in nested mode.

## Composed Config (`composed.py`)

`build_composed_config(registrars, *, inline_wiring=True, top_level_extra="forbid")` builds one top-level model from several layers.

### Build order

1. Argument checks: `registrars` must map section names to registrars (`TypeError`), `top_level_extra` must be a known mode (`ValueError`), section names must be usable as fields (below).
2. Empty layers: one `EmptyLayerError` naming all of them.
3. Each layer's own checks, as in `build_layer_config`.
4. `validate_wiring(registrars)`: every wiring problem of the build in one `WiringResolutionError`.
5. With `inline_wiring=False`, inline-only layers are refused.
6. The layers are built leaves first, and wired fields are inlined (below).
7. The top-level model is built.

Model names are unique across the whole build.

### Section names

The key a registrar is passed under names its top-level section and becomes a field of the top-level model and of the generated source, so it must be a valid identifier, not a keyword, not private (`_x`), not a `BaseModel` attribute (`model_config`, `schema`, `json`, `copy`, `dict`, `validate`, ...) and without pydantic's `model_` prefix. A `ConfigDeclarationError` names every bad name with a replacement. Wiring entries find layers by their registry name, so renaming a section changes nothing else.

### Dependency order

A layer depends on the layers its classes wire to (`declare_only` entries add no dependency). Layers are sorted leaves first; a cycle raises `CircularWiringError` naming one actual cycle (`agent -> loop -> agent`). A wiring entry that targets a registry passed under several section names is a `ConfigDeclarationError`.

### The top-level model

`ComposedConfig` has a `list[<layer union>]` field, defaulting to `[]`, for every layer except the inline-only ones (below). `top_level_extra` sets its extra policy: `"forbid"` (default) refuses unknown sections, so a misspelled `hooks:` is caught, and the JSON Schema says `additionalProperties: false`; `"ignore"` drops them; `"allow"` keeps them in `model_extra`.

### Inline-only layers

A layer declared with `create_registrar(..., inline_only=True)` has no top-level section: its instances may only be written inside receptors of other layers. Its models are still built (receptors use them), but the top-level model holds a hidden phantom field for it (`SkipJsonSchema[Any] = Field(default=None, exclude=True)`) with a validator that refuses any value written there, `[]` and `null` included, in every `top_level_extra` mode. The error has type `inline_only_layer` and `loc == (layer,)`, is reported together with the input's other errors, and names every writable location:

```
layer 'archiver' is inline-only; write its instances under: hook[trace_writer].archive
```

A location is a receptor with a runtime slot (`declare_only` entries never count) wired to the layer and holding inline configs in this build, written `owner_layer[owner_key].receptor`. A slot-less receptor can hold inline configs, but does not qualify as a writable location for this check; declare a constructor parameter or class annotation for it. Through inline-only owners the full path is shown (`env[browser].hooks[trace_writer].archive`), and such a path only counts when every receptor on it accepts the next owner's key. Locations are joined with `" or "` and listed in `ComposedConfigResult.inline_only_layers`. An inline-only layer without any writable location is a `ConfigDeclarationError`, and so is `inline_wiring=False` with an inline-only layer in the build.

### Inline wiring

With `inline_wiring=True`, every wired field whose target layer is in the build is retyped from key selector to config holder:

- a single-instance receptor becomes the target layer's union (`Optional[...]` when the annotation admits `None`); a container receptor becomes `list[<union>]`;
- a key subset (Mode 2, or key constraints that narrowed the keys) gets a subset union that keeps the target layer's discriminator (flat `Field(discriminator=...)`, or nested `Discriminator` + `Tag`);
- the field keeps its title, description, aliases and deprecated marker, and `min_length` / `max_length` on list receptors; examples and the metadata pydantic interprets are dropped (they were written for the key string), plain markers stay;
- `declare_only` entries are never inlined: they stay the `Optional[Literal[...]] = None` key constraint, so no config block is accepted that nothing receives. Slot-less entries without `declare_only` are inlined (the framework injects those attributes);
- Mode 3 lists and wiring to layers outside the build stay key selectors.

The owning model is rebuilt by subclassing it, so validators are inherited. Validators of an inline-wired model therefore see a nested config (or a list of them) where the per-layer model passes a key string. Each rebuilt model records what was inlined in `__inline_wired__` (`{field: {"target_layer", "keys", "container", "optional"}}`).

#### Default instances

A single-instance receptor with a default key (the dict-form `default`, or a wired parameter whose own default is a key string such as `loop: str = "react"`) defaults to that key's config built from defaults: `Field(default_factory=<final per-key model>, json_schema_extra={"default": <dump>})`, where the final per-key model is the target layer's model for that key as this build finally defines it (after its own receptors were inlined). An omitted block validates to a config indistinguishable from an explicit `{<discriminator>: <key>}` block. The target config must be buildable from defaults, otherwise `ConfigDeclarationError` names its required fields. `null` is refused unless the receptor's annotation admits `None` (then omitted means the default instance and `null` means `None`).

A list receptor may default to an empty collection, a container factory or `None`. A non-empty list of keys is accepted in a per-layer build but raises `ConfigDeclarationError` when inlined. On a single-instance receptor a surviving `default_factory`, or a default that is neither a key string nor `None`, also raises `ConfigDeclarationError` under inline wiring. Pure factories already reduced to literal defaults during extraction follow the literal-default rules.

An inline-only `archiver` layer whose configs are written inside the `archive` receptor of a `hook`, with `disk` as the default key:

## Code generation (`codegen.py`)

`generate_layer_config_source(result)` and `generate_composed_config_source(result)` write a self-contained module whose models validate like the in-process ones. The one exception is validator metadata the file cannot write ([below](#the-value-ladder)), which only the in-process models enforce.

### Layout

The first line is `# Generated by conscribe <version>`, followed by the layer information and, when applicable, the degraded fields and the metadata the file cannot carry. Then come `from __future__ import annotations` and the imports, nested segment models (deepest first), the per-key classes in key order and their `model_rebuild()` calls, the nested-mode `_discriminate_<layer>` function and, for a layer with more than one key, the union alias (its members in the in-process union's order). A composed file adds, per layer in dependency order, the models and the layer's alias, then the top-level `ComposedConfig` (its `extra` policy, `json_schema_extra`, the phantom fields and the inline-only refusal validator) and a final `ComposedConfig.model_rebuild()`, so the file also works when exec'd into a plain dict. Inline unions are written with their discriminators: the layer's alias when the field accepts every key, an inline `Annotated[Union[...], ...]` for a subset. The output is deterministic.

### What the file defines and what it imports

The file defines only models conscribe generated (marked `__conscribe_generated__`). Every other type it references (your enums, models, classes) is imported by identity, with deterministic aliases when two names collide. Imports from `conscribe.*` and of function-local types are refused (`ConfigRenderError`); a type imported from `__main__` gets an `ExtractionWarning`.

### Fields

A required field is `name: T` (or `name: T = Field(<keywords>)`); a default uses the keyword form `Field(default=...)` when other keywords are present. Every constraint is written as a `Field` keyword, also inside type arguments (`list[Annotated[float, Field(ge=0)]]`); tuples are `tuple[str, ...]` / `tuple[()]`; a field whose name shadows a `BaseModel` attribute gets an explicit `Field(...)`. Generated submodel defaults are `Field(default_factory=Sub)`.

### The value ladder

A default is written by the first rung that reproduces it exactly, each checked against the real object:

1. a literal whose `repr` round-trips through `ast.literal_eval`;
2. an Enum member (imported);
3. a constructor form checked with `eval` (`Path(...)`, timezone-aware `datetime(...)`, `Decimal(...)`, `re.compile(...)`, ...);
4. the JSON form plus `validate_default` (field defaults only);
5. an importable module-level object found by identity;
6. otherwise `ConfigRenderError` naming the model, the field and the value. No file text is returned then.

Metadata the file cannot write (a validator wrapping a lambda, `Predicate(lambda ...)`) stays enforced by the in-process model; the file drops it, notes it in the header and next to the field, and `generate_*_source` emits an `ExtractionWarning`.

## JSON Schema (`json_schema.py`)

For one layer, `generate_layer_json_schema(result)` is pydantic's JSON Schema of `result.union_type`, plus extensions a union cannot carry itself:

- `x-discriminator`: the discriminator field (nested mode: the level-0 one);
- `x-discriminator-fields` and `x-key-separator` in nested mode;
- for degraded fields, a top-level `x-degraded-fields` (`{key: [{field, original_type}]}`) and, on each degraded property, `x-degraded-from` and a `[degraded]` note in its description.

For a composed build, `generate_composed_json_schema(result)` *is* `result.top_level_type.model_json_schema()`. The extensions `x-composed-layers`, `x-inline-wiring`, `x-inline-only-layers` (`{layer: [paths]}`) and, under `top_level_extra="ignore"` / `"allow"`, a `not: {anyOf: [{required: [layer]}, ...]}` clause refusing inline-only names, all live in the model's `json_schema_extra`, so conscribe adds nothing after pydantic generates the schema.

Both schemas write the members of set-valued defaults in a canonical order, so files do not change with `PYTHONHASHSEED`. Values you put into `examples` or `json_schema_extra` are written as given.

## Three artifacts, one config

The in-process models, the generated source and the published JSON Schema share the config's fields, defaults and schema-expressible constraints:

- the generated source defines the same models with the same fields, defaults, constraints, discriminators, validators it can write, inline-only refusal and legacy-flat guard;
- the published composed schema equals the in-process model's own schema, extensions included;
- whatever conscribe cannot reproduce faithfully is an error (`ConfigRenderError`) or, for validators only, reported (`ExtractionWarning` and a header note).

conscribe's test suite checks this with a parity harness: it loads the generated source as a module, compares its models' JSON schemas with the in-process ones, validates the same valid and perturbed payloads against both (accepted values must dump equal, rejected ones must fail with the same error types, locations and messages), and compares the published schema with the in-process schema.

An `ExtractionWarning` for omitted validation metadata marks an exception to source parity: that check still runs in-process but does not run in the generated module. JSON Schema also cannot express arbitrary Python validators; it describes the schema that pydantic exposes for them.

## Fingerprint (`fingerprint.py`)

`compute_registry_fingerprint(registrar)` returns 16 hex characters of a SHA-256 over:

- `conscribe.__version__`;
- the layer settings that only show in composed output: layer name, discriminator field(s), key separator, `inline_only`;
- the layer's generated source, `generate_layer_config_source(build_layer_config(registrar))`;
- the layer's JSON Schema, serialized with sorted keys.

The fingerprint changes exactly when regenerating would change the layer's outputs: a field's type, default, description or constraint, the keys a wired field allows (a target registry gaining a key widens its `Literal`), a wiring default, `declare_only`, the registered keys and their order, a conscribe upgrade. Edits that do not reach the outputs (comments, a class docstring's summary, the body of a factory the generated file imports by reference) leave it unchanged. It is the same in every process and on every Python version whenever the outputs are. Every fingerprint changes once when you upgrade conscribe.

It never raises: a layer that cannot be generated (a wiring problem, a typo in an annotation, no registered class) hashes a stable marker `error:<ExceptionType>:<message>` (object addresses removed), which differs from the repaired layer's fingerprint. Warnings are suppressed while computing.

A composed build with inline wiring embeds the target layers' unions in the owners' models; fingerprint every layer of the build to cover it.

The fingerprint does not cover `.pyi` stubs. Regenerate stubs separately when the classes' methods or injected attributes change.

